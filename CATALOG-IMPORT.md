# Catalog Import

## Model
Catalog import accepts exactly one XLSX worksheet and one Track per data row.

Canonical columns, in order:

1. Música
2. Nome do Lançamento
3. Tipo de Lançamento
4. Número da Faixa
5. Artista Principal
6. Participação / Feat
7. Data de Lançamento
8. Idioma
9. Gênero
10. Subgênero
11. Explícita
12. Versão
13. Duração
14. ISRC
15. Pré-save
16. Spotify
17. Apple Music
18. Deezer
19. YouTube
20. Observações

The template is generated by repository code; there is no drifting binary source template.

## Required fields
Always required: Música, Tipo de Lançamento and Artista Principal.

SINGLE defaults blank Nome do Lançamento to Música and defaults missing/invalid track number to 1.

EP/ALBUM require Nome do Lançamento and Número da Faixa.

Multiple artists use semicolon separators only.

## Normalization
Release type maps PT-BR labels to SINGLE/EP/ALBUM. Duration Min:Seg becomes integer milliseconds. Explicit values accept clear Sim/Não. Dates normalize without timezone shifting. Language uses Reference Data. Genre/subgenre resolve MUSIC_GENRE labels/aliases and hierarchy. ISRC is normalized locally and is not externally verified. Platform URLs require HTTPS.

## Pipeline
upload → parse → validate → normalize → deduplicate → preview → resolve → confirm → import.

Upload never directly creates catalog entities.

## Duplicate rules
- Artist: exact normalized name inside the current Workspace access set may match EXISTING. Global same-name candidates without current access become POSSIBLE_DUPLICATE.
- Release: normalized title + type + primary Artist + date is deterministic matching evidence.
- Track: exact ISRC is a strong signal. Conflicting ISRC is invalid/needs resolution; title alone never auto-merges.
- POSSIBLE_DUPLICATE never auto-merges and requires explicit resolution.

## Idempotency
music_import_sessions has a Workspace + source file fingerprint uniqueness invariant. Re-preview of the same file returns the existing session. Re-confirmation of an IMPORTED session returns existing provenance and does not create duplicate entities.

## Safe fill / conflicts
Existing non-empty catalog fields are never silently overwritten by import. Current import either links an existing confidently matched Track or creates new entities after preview/resolution.

## Provenance
Import session stores Workspace, actor, source filename, fingerprint, row count, lifecycle and timestamps. Each row stores source row number, fingerprint, classification, normalized data, errors, explicit resolution and created/matched entity IDs.

The original XLSX bytes are not persisted.

## Security limits
- maximum workbook size: 5 MiB;
- maximum data rows: 1000;
- exactly one worksheet;
- hidden sheets rejected;
- external workbook relationships rejected;
- malformed ZIP/XLSX rejected;
- unsupported compression rejected;
- decompressed entry size bounded;
- unexpected columns rejected;
- formulas are treated as text data and never evaluated;
- XLSX contains metadata only; audio and artwork remain Shared Media flows.
